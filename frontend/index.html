↔ Relationship Map
AIRLINES → FLIGHT 1 : N

One airline operates multiple flights.

PASSENGER → RESERVATION 1 : N

One passenger can make multiple reservations.

AIRPORT → RESERVATION 1 : N

Departure and arrival airports are referenced by reservations.

RESERVATION → TICKET 1 : N

A reservation can contain multiple tickets.

RESERVATION + TICKET → PAYMENT 1 : N

Payments reference the ticket composite key.

BAGGAGE → BAGGAGE_TRACKING 1 : N

A baggage item can have multiple tracking scans.

TICKET ↔ BAGGAGE M : N

Mapped through the TICKET_BAGGAGE relation table.

PASSENGER → PASSENGER_PHONE 1 : N

A passenger can have multiple phone numbers.

Relational Mapping

How EER concepts are represented in the relational schema

01

Multivalued Attribute

The multivalued Phone attribute of PASSENGER is mapped to the PASSENGER_PHONE relation.

02

M:N Relationship

The TICKET ↔ BAGGAGE many-to-many relationship is represented using TICKET_BAGGAGE.

03

Composite Keys

TICKET, BAGGAGE_TRACKING, TICKET_BAGGAGE and PASSENGER_PHONE use composite primary keys.

04

Foreign Keys

Foreign keys maintain referential integrity between related relations.
